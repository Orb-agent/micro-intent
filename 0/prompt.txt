  ## Gemini and Workspace MCP for a TypeScript (Node 22) voice agent — research as of 2026-10-10
  
  I checked everything against the live docs, the js-genai source, npm, and unauthenticated probes of the MCP endpoints. I wrote no project files and deleted my temporary downloads.
  
  ### Findings that change the plan
  1. **`gemini-3.5-flash` is deprecated (Oct 8, 2026).** Requests to it are now automatically served by `gemini-3.6-flash`. Use `gemini-3.8-flash` (current GA) or `gemini-3.6-flash` instead.
  2. **Google now labels `generateContent` "legacy".** It "remains fully supported", but Google recommends the Interactions API for new code. My answers cover `generateContent`, because that is where `parametersJsonSchema`, `toolConfig` and `mcpToTool` live. The Interactions equivalents are listed in §2.
  3. **`mcpToTool` cannot be mixed with your own function under automatic function calling.** With AFC on (the default), `mcpToTool(...)` plus a plain `functionDeclarations` tool throws. You must turn AFC off and run the loop yourself (§5).
  4. **Workspace MCP servers are Developer Preview only.** Preview features "may not be included in public applications" before GA. You must also screen prompts and responses for prompt injection (§6).
  
  ### 1. Model ids
  - **`gemini-3.5-flash`** was released GA-only on May 19, 2026. There was never a `-preview` id on the Gemini API; the preview of that line was `gemini-3-flash-preview`. It was deprecated Oct 8 with no shutdown date announced.
  - **Current options:**
    - `gemini-3.8-flash`: GA Sep 2. Default thinking is `medium`; `minimal` returns an error.
    - `gemini-3.6-flash`: GA Jul 21. Supports `minimal`.
    - `gemini-3.5-flash-lite`: defaults to `minimal`.
  - **Gemini 3.6 and later:**
    - `temperature`, `top_p` and `top_k` are deprecated and ignored now, and will return a 400 in future models.
    - A request whose last turn is a prefilled model turn returns a 400.
  - **UNVERIFIED:** which model `gemini-flash-latest` currently points to.
  
  ### 2. Function calling in `@google/genai` (latest 2.28.0, Oct 7)
  - **`FunctionDeclaration.parametersJsonSchema` exists.** It must describe an object and cannot be combined with `parameters`.
  - **Documented JSON Schema keywords:**
    - `type` (including `"null"` inside a type array), `title`, `description`
    - `properties`, `required`, `additionalProperties`, `enum`, `format`
    - `minimum`/`maximum`, `items`, `prefixItems`, `minItems`/`maxItems`
    - `anyOf` appears in Google's examples, and Google's Nov 2025 post added `anyOf` and `$ref`.
  - **`oneOf` and `const` are not documented (UNVERIFIED).** A Sep 2026 forum post reports a 400 on `gemini-3.8-flash` for a schema containing `const`, `$defs` and `anyOf`. For a discriminated union of card kinds:
    - Use `anyOf` of objects, each with a one-value `enum` on `kind`.
    - Validate the arguments with Zod.
    - In `ANY` mode the API "may reject very large or deeply nested schemas", so keep the card schema shallow.
  - **Parallel calls:** one response can contain several `functionCall` parts.
    - Send back exactly one `functionResponse` per call, with matching `id` and `name`, in any order.
    - History must be ordered FC1(+signature), FC2, FR1, FR2. Interleaving FC and FR returns a 400.
    - On `generateContent`, mismatched ids don't error. Instead the model tends to return empty responses with finish reason `STOP`.
  - **Modes:** `AUTO | ANY | NONE | VALIDATED`. `allowedFunctionNames` is only valid with `ANY` or `VALIDATED`.
  - **Thinking for low latency:** `thinkingConfig.thinkingLevel = LOW` on 3.8 Flash, or `MINIMAL` on 3.6 Flash / 3.5 Flash-Lite. Sending both `thinkingLevel` and `thinkingBudget` returns a 400.
  - **Thought signatures must be echoed back on Gemini 3.** Leaving them out of function-calling history returns a 400.
    - The signature sits on the first `functionCall` part of each step; with parallel calls, only the first call has one.
    - Push `candidates[0].content` back unmodified and never merge parts.
    - For calls you inject yourself, the dummy signature `"skip_thought_signature_validator"` bypasses validation.
  - **Interactions API equivalents** (snake_case in the JS SDK):
  
  | Concept | Interactions API |
  |---|---|
  | Declare a function | `{type:'function', name, description, parameters}` |
  | Force a call | `generation_config.tool_choice.allowed_tools = {mode:'any', tools:[...]}` |
  | Thinking | `generation_config.thinking_level` |
  | Send a result | `{type:'function_result', call_id, name, result}` |
  | Server-side MCP | `{type:'mcp_server', name, url, headers, allowed_tools}` (Streamable HTTP only) |
  
    Using that server-side MCP tool against the Workspace servers is UNVERIFIED.
  
  ```ts
  import { GoogleGenAI, FunctionCallingConfigMode, ThinkingLevel, PartMediaResolutionLevel,
           mcpToTool, type Content } from '@google/genai';
  import { Client } from '@modelcontextprotocol/sdk/client/index.js';
  import { StreamableHTTPClientTransport } from '@modelcontextprotocol/sdk/client/streamableHttp.js';
  
  const ai = new GoogleGenAI({ apiKey: process.env.GEMINI_API_KEY });
  const cal = new Client({ name: 'voice-agent', version: '1.0.0' });
  await cal.connect(new StreamableHTTPClientTransport(new URL('https://calendarmcp.googleapis.com/mcp/v1'),
    { requestInit: { headers: { Authorization: `Bearer ${userAccessToken}` } } }));
  
  const respond = { name: 'respond', description: 'Always the final call of a turn.',
    parametersJsonSchema: { type: 'object', required: ['speech', 'cards'], properties: {
      speech: { type: 'string' },
      cards: { type: 'array', items: { anyOf: [   // not oneOf/const (UNVERIFIED)
        { type: 'object', required: ['kind', 'eventId'],
          properties: { kind: { type: 'string', enum: ['event'] }, eventId: { type: 'string' } } },
        { type: 'object', required: ['kind', 'threadId'],
          properties: { kind: { type: 'string', enum: ['email'] }, threadId: { type: 'string' } } },
      ] } } } } };
  
  const config = {
    tools: [mcpToTool(cal), { functionDeclarations: [respond] }],
    automaticFunctionCalling: { disable: true },    // required when mixing, otherwise the SDK throws
    toolConfig: { functionCallingConfig: { mode: FunctionCallingConfigMode.ANY } }, // every step is a call
    thinkingConfig: { thinkingLevel: ThinkingLevel.LOW },
  };
  
  async function runTurn(png: Buffer, transcript: string) {
    const contents: Content[] = [{ role: 'user', parts: [
      { inlineData: { mimeType: 'image/png', data: png.toString('base64') },
        mediaResolution: { level: PartMediaResolutionLevel.MEDIA_RESOLUTION_HIGH } },
      { text: transcript } ] }];
    for (let step = 0; step < 6; step++) {
      const res = await ai.models.generateContent({ model: 'gemini-3.8-flash', contents, config });
      contents.push(res.candidates![0].content!);   // keeps the thoughtSignature parts intact
      const calls = res.functionCalls ?? [];
      const end = calls.find(c => c.name === 'respond');
      if (end) return end.args; // before the next user turn, also append a functionResponse {id, name} for it
      contents.push({ role: 'user', parts: await Promise.all(calls.map(async c => ({ functionResponse: {
        id: c.id, name: c.name,
        response: (await cal.callTool({ name: c.name!, arguments: c.args })) as Record<string, unknown> } }))) });
    }
  }
  ```
  
  ### 3. Built-in tools together with custom functions
  This works on Gemini 3 only and is still Preview.
  
  ```ts
  tools: [{ googleMaps: {} }, { googleSearch: {} }, { functionDeclarations: [respond] }],
  toolConfig: { includeServerSideToolInvocations: true,
                retrievalConfig: { latLng: { latitude: 52.37, longitude: 4.9 } } },
  ```
  
  - With that flag on, the default mode is `VALIDATED` and `AUTO` is not supported.
  - You must send back every returned part (`toolCall`, `toolResponse`, `functionCall`, each with its `thoughtSignature`). Appending the whole candidate content handles this.
  - Maps and Search together are supported on 3.5 Flash-Lite and later.
  - **Maps grounding limits:**
    - It "does not currently support multimodal inputs", which conflicts with sending a screenshot in the same request.
    - Google Maps sources must be shown to the user with attribution.
    - Pricing is $14 per 1,000 queries after 5,000 free per month.
  - **UNVERIFIED:** whether `ANY` mode works together with built-in tools.
  
  ### 4. Image input
  - **Format:** `{inlineData: {mimeType, data: base64}}`. Accepted types are png, jpeg, webp, heic and heif. Up to 3,600 images per request.
  - **Size limit:** the file-input-methods page says 100 MB per request, but the image-understanding page still says 20 MB. The docs disagree.
  - **Media resolution:**
    - Global: `config.mediaResolution` set to `MEDIA_RESOLUTION_LOW`, `MEDIUM` or `HIGH`.
    - Per part (Gemini 3, experimental): `part.mediaResolution = {level}`. `ULTRA_HIGH` is only available per part.
  - **Gemini 3 image tokens:**
  
  | Setting | Tokens |
  |---|---|
  | LOW | 280 |
  | MEDIUM | 560 |
  | HIGH (= default) | 1120 |
  | ULTRA_HIGH | 2240 |
  
    Google recommends HIGH for images; use LOW if latency matters more than detail.
  
  ### 5. `mcpToTool`
  - **Status:** experimental. It is marked `@experimental` in the source, and the docs say tools only (no resources or prompts) and breaking changes are possible.
  - **Dependencies:** optional peer dependency `@modelcontextprotocol/sdk ^1.25.2` (latest 1.32.1). It converts each MCP tool's `inputSchema` to `parametersJsonSchema` and `outputSchema` to `responseJsonSchema`.
  - **Mixing with your own function:**
    - With AFC on, the SDK throws "Automatic function calling with CallableTools (or MCP objects) and basic FunctionDeclarations is not yet supported".
    - With `automaticFunctionCalling.disable: true` it doesn't throw; it still expands the MCP tools into declarations and you run the loop.
    - AFC only stops when a response has no function calls (default limit 10), so it could never end on a final `respond` call anyway.
  - **Possible bug, seen in source, effect not tested:** the SDK's MCP tool runner builds `functionResponse` without an `id`. On Gemini 3 that risks empty replies, so set `id` yourself, as the snippet does.
  - **What the unauthenticated probes of `calendarmcp` showed:**
    - `initialize` with protocol version `2025-11-25` succeeds (server name "StatelessServer", plain JSON responses, no session id). So the v1 SDK `Client` connects fine.
    - `tools/list` works without auth.
    - `tools/call` without a token returns 401 with `WWW-Authenticate: Bearer resource_metadata=...`, pointing to `https://accounts.google.com/`.
  - **Schema risk (UNVERIFIED):** the live Workspace input schemas contain `$defs`/`$ref`, `readOnly`, `deprecated` and `x-google-enum-descriptions`. I couldn't confirm Gemini accepts these as-is. If you get a 400, build the declarations yourself from `client.listTools()` with those keywords removed and `$ref` inlined.
  
  ### 6. Workspace remote MCP servers (Developer Preview)
  - **Endpoints** (Streamable HTTP):
    - Gmail: `https://gmailmcp.googleapis.com/mcp/v1`
    - Calendar: `https://calendarmcp.googleapis.com/mcp/v1`
    - Drive: `https://drivemcp.googleapis.com/mcp/v1`
    - Docs, Sheets, Slides and Chat follow the same pattern; People is at `people.googleapis.com/mcp/v1`.
  - **Enabling them:**
    1. Join the Workspace Developer Preview Program through its form. Google registers your Workspace account and Cloud project, which takes "a couple of days".
    2. Enable the regular APIs and the MCP services: `gcloud services enable gmail.googleapis.com calendar-json.googleapis.com drive.googleapis.com gmailmcp.googleapis.com calendarmcp.googleapis.com drivemcp.googleapis.com`.
    3. Set up the OAuth consent screen (Internal, or External with test users).
    4. Create a Web OAuth client.
  - **Auth:** the user's OAuth 2.0 access token, sent as `Authorization: Bearer <token>`.
  - **Scopes in Google's guide only cover reads and drafts:**
    - Gmail: `gmail.readonly`, `gmail.compose`
    - Drive: `drive.readonly`, `drive.file`
    - Calendar: `calendar.calendarlist.readonly`, `calendar.events.freebusy`, `calendar.events.readonly`
    - Calendar writes need `calendar.events`. Gmail label, trash and spam tools need `gmail.modify`.
  - **Calendar tools (9):**
    - Read:
      - `list_events`: `startTime`/`endTime` are local ISO times with no offset and no `Z`; `timeZone` is an IANA id; page size up to 250.
      - `get_event`
      - `list_calendars`
      - `search_events`: semantic search, primary calendar only.
      - `suggest_time`: proposes free slots.
    - Write: `create_event`, `update_event`, `respond_to_event`, `delete_event` (destructive).
  - **Gmail tools (the docs list 10; the live `tools/list` returns 23):**
    - Read:
      - `search_threads`: Gmail query syntax, page size up to 50, returns snippets only, labels must be given as IDs.
      - `get_thread` and `get_message`: Google recommends `messageFormat` `PLAIN_TEXT`.
      - `list_drafts`, `get_draft`, `list_labels`
    - Write: `create_draft`, label/unlabel on threads and messages, `update_message_labels`, `create_label`.
    - Destructive tools that only appear in the live list: trash, spam and sensitive-label tools.
    - There is no send tool; the agent can only create drafts.
  - **Drive tools (8):**
    - Read: `search_files`, `list_recent_files`, `read_file_content` (natural-language rendering), `download_file_content` (base64), `get_file_metadata`, `get_file_permissions`.
    - Write: `create_file`, `copy_file`.
  - **Limitations:**
    - Preview terms forbid use in public apps before GA.
    - Google requires screening prompts and responses for prompt injection, either with Model Armor or a documented solution of your own.
    - Google says the servers speak MCP version 2026-07-28 (stateless), but the older 2025-11-25 handshake works.
    - **UNVERIFIED:** whether consumer @gmail.com accounts can use these servers, and real tool calls with a token.
  
  ### 7. REST fallbacks (confirmed)
  - **Gmail list:** `GET https://gmail.googleapis.com/gmail/v1/users/me/messages?q=...&maxResults=...&pageToken=...`
    - Also takes `labelIds` and `includeSpamTrash`. Default 100 results, max 500.
    - Returns only `id` and `threadId`.
    - `q` is not allowed with the `gmail.metadata` scope.
  - **Gmail get:** `GET .../users/me/messages/{id}?format=full`
    - Formats are minimal, full, raw and metadata; use `metadataHeaders` with metadata.
    - Body data is base64url-encoded.
  - **Calendar events:** `GET https://www.googleapis.com/calendar/v3/calendars/primary/events?timeMin=...&timeMax=...&singleEvents=true&orderBy=startTime`
    - Times must be RFC3339 with an offset.
    - `timeMin` filters on event end and `timeMax` on event start (exclusive).
    - `orderBy=startTime` requires `singleEvents=true`.
    - `maxResults` defaults to 250, max 2500. Also takes `q` and `timeZone`.
